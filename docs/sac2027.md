# v3: SAC 2027 extension

This version extends the FSE 2027 pipeline (v2) to study *how* analyzer
findings disappear during repair: fixed, rewritten in place, moved to another
function, replaced by a call with the same CWE, or removed and then returned.
It reuses the v2 data, adds an offline analysis, and adds two repair arms
that need new runs.

| Version | Paper | Code | Guide |
|---|---|---|---|
| v1 | ISE 2026, *All That Glitters is Not Gold* | `v1/` | `v1/README.md` |
| v2 | FSE 2027 submission | `src/`, `config/` | `docs/reproduction.md`, `docs/architecture.md` |
| v3 | SAC 2027 submission | v2 code + the files below | this file |

## What v3 adds

| File | Purpose |
|---|---|
| `src/pipeline/finding_track.py` | Shift-robust finding keys (rule, enclosing function, normalized line, occurrence) and the repair-history notes |
| `src/pipeline/comment_inject.py` | `static+history` and `static+dynamic+history` feedback modes: same findings and stopping rule as `static` / `static+dynamic`, plus a `/* Repair history */` block naming findings that moved or were replaced since the previous round |
| `src/pipeline/run_experiment.py` | `--gen-source-model`: import round-0 programs from another registry id |
| `config/models.yaml` | `*-repairthink` ids: the `*-thinking` settings under a separate id, so repair-only reasoning cells get their own directory |
| `src/analysis/relocation.py` | Counts relocation, substitution, reappearance and related events per model and cell |
| `src/analysis/relocation_sample.py` | Draws the stratified sample for manual validation |
| `results/sac2027/` | v3 outputs (reports, event lists, validation sheet) |
| `paper/sac2027/` | Paper sources (`refs.bib`, `sections/`, `macros.tex`) |

## 1. Offline analysis (no API cost)

Uses the v2 cells already in `data/collected_code_6/`. Python 3.10+ with the
repository's requirements; no analyzers or keys are needed.

```bash
# Event counts for the 7 models, static-only and full-gate cells, rounds 0..5
python -m src.analysis.relocation

# 150 events (one per program, balanced across models) for two annotators
python -m src.analysis.relocation_sample --n 150 --seed 2027
```

Outputs in `results/sac2027/`: `relocation.md` (tables), `relocation.json`,
`relocation_events.csv` (every cross-function event), `relocation_sample.md`
(code before and after each sampled event) and `relocation_sample.csv`
(label sheet: SAME, FIX+NEW, BENIGN, UNCLEAR, as defined in
`relocation_sample.py`).

## 2. New repair arms (need API keys and the v2 toolchain)

Both arms repair the **same round-0 programs** as the v2 baseline cell
`feedback-static-r0-t1.0-p1.0` (reasoning off), on the 200-task subset, with
static feedback and the configured 5-round horizon. The round-0 programs and
their static reports are copied, not regenerated, so differences come from
the repair step only. Set up keys, tools and proxy exactly as in
`docs/reproduction.md`.

| Arm | Question | What changes vs. the baseline |
|---|---|---|
| A (baseline) | none, already collected | nothing to run |
| B: repair-only reasoning | Does reasoning help when it is enabled only during repair? | reasoning on during repair |
| C: repair history | Does telling the model that a finding moved or was replaced reduce relocation and substitution? | `+history` feedback |

```bash
# Arm B: reasoning on during repair only (models with a reasoning toggle)
for m in deepseek-v4-pro openai-gpt56-sol kimi-k3 glm-5.1; do
  python -m src.pipeline.run_experiment --model "$m-repairthink" \
    --feedback static --tasks subset --samples 3 \
    --gen-source feedback-static-r0-t1.0-p1.0 --gen-source-model "$m" \
    --gen-source-reports
done

# Arm C: repair-history feedback, reasoning off
for m in deepseek-v4-pro openai-gpt56-sol kimi-k3; do
  python -m src.pipeline.run_experiment --model "$m" \
    --feedback static+history --tasks subset --samples 3 \
    --gen-source feedback-static-r0-t1.0-p1.0 --gen-source-reports
done
```

Where the data lands:

| Arm | Cell directory | Manifest |
|---|---|---|
| B | `data/collected_code_6/<model>-repairthink/feedback-static-r1-t1.0-p1.0/` | `results/<model>-repairthink/feedback-static-r1-t1.0-p1.0.manifest.json` |
| C | `data/collected_code_6/<model>/feedback-static+history-r0-t1.0-p1.0/` | `results/<model>/feedback-static+history-r0-t1.0-p1.0.manifest.json` |

Estimated cost (worst-case input pricing, from the v2 usage ledgers; actual
cost is usually lower):

| Plan | Arm B | Arm C | Total |
|---|---|---|---|
| `--samples 1` | about US$42 (up to 93) | about US$20 (up to 40) | about US$62 |
| `--samples 3` | about US$121 (up to 267) | about US$57 (up to 115) | about US$178 |

Without GPT-5.6 Sol, arm B drops to about US$23 (`--samples 1`) or US$66
(`--samples 3`). Each model and arm takes about 2 to 5 hours at the default
concurrency; models on different providers can run in parallel. Arm C uses
models with high relocation or substitution rates in v2 (GPT-5.6 Sol 15.1%
cross-function moves, Kimi K3 and DeepSeek V4 Pro about 14% same-CWE
substitutions); Claude Fable 5 (11.1% moves) is a useful but more expensive
addition.

## 3. Analysis of the new arms

```bash
# Baseline restricted to the same tasks
python -m src.analysis.relocation --tasks subset \
  --models deepseek-v4-pro openai-gpt56-sol kimi-k3 glm-5.1 \
  --slug feedback-static-r0-t1.0-p1.0 --name arm_a
# Arm B
python -m src.analysis.relocation --tasks subset \
  --models deepseek-v4-pro-repairthink openai-gpt56-sol-repairthink kimi-k3-repairthink glm-5.1-repairthink \
  --slug feedback-static-r1-t1.0-p1.0 --name arm_b
# Arm C
python -m src.analysis.relocation --tasks subset \
  --models deepseek-v4-pro openai-gpt56-sol kimi-k3 \
  --slug feedback-static+history-r0-t1.0-p1.0 --name arm_c
```

When the arms ran with `--samples 1`, add `--samples 1` to all three
commands so the baseline covers the same programs. Paired tests (same
program in two arms) follow the v2 statistics module
(`src/analysis/stats.py`).
